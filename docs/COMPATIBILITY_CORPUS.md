# Compatibility corpus acquisition record

This record defines how Stage 8 obtains non-repository GIF inputs for host-side compatibility and malformed-input testing. It records provenance and expected use before a file may influence a regression expectation.

## Repository boundary

Downloaded conformance corpus files are kept under `testdata/compatibility_corpus/`, a durable local test-data location excluded explicitly by `.gitignore`. No GIF binary, upstream checkout, generated derivative, fuzz input, or raw host result from this activity is staged or pushed. `_TEMP/` remains reserved for disposable experiment material. This document, test code, and small project-original byte fixtures may be committed separately when they are ready for public review.

Every selected external file must have a recorded source URL, upstream revision, filename, SHA-256 digest, declared license, expected decoder result, and feature rationale. A file with missing or uncertain redistribution terms may be used only as local investigative material and must not become a committed fixture or a claimed compatibility result.

## Initial source: imazen GIF Conformance suite

The initial local acquisition source is [imazen/codec-corpus](https://github.com/imazen/codec-corpus), restricted by sparse checkout to `gif-conformance/`.

The first local acquisition is pinned to upstream commit `28205bbc5cf40364d012c462240ba28143373d67`. It contains all 39 GIF files documented by upstream: 28 under `valid/`, 7 under `invalid/`, and 4 under `edge-cases/`. The checkout path is `testdata/compatibility_corpus/codec-corpus/gif-conformance/`.

The upstream project describes this subset as 39 generated GIF89a files: 28 valid files, 7 invalid files, and 4 edge-case files. Its documented coverage includes disposal methods, transparency, timing, looping metadata, local and global colour tables, interlace, frame offsets, canvas/frame geometry, GIF87a/GIF89a, and comment/plain-text extensions. The upstream record states that the suite is generated by its Python standard-library generator and is CC0 1.0/public-domain material.

This makes it suitable for local compatibility investigation without importing unknown artwork. It does not override this library's documented feature boundary: disposal method 3, Graphic Control Extension user-input requests, and any deliberately unsupported extension remain expected `GIF_STATUS_UNSUPPORTED_FEATURE` cases rather than success cases.

## Local selection policy

The initial sweep will classify every locally acquired file into one of these categories before adding a regression assertion:

| Category | Expected use |
| --- | --- |
| Supported-valid | Must open and decode through normal EOS with the documented output semantics. |
| Forward-version compatibility | Declares a later GIF version but uses only semantics supported by this decoder; must decode through normal EOS under the capability-oriented best-effort header policy. |
| Malformed | Must fail with a stable public error and must not hang, leak, or corrupt allocator state. |
| Deliberately unsupported | Must return `GIF_STATUS_UNSUPPORTED_FEATURE`; this is not a decoder defect. |
| Specification edge | Investigate and document the observed result before assigning a stable expectation. |

The local manifest will record parser-observed features and digests. Before any future decision to commit a binary fixture, re-check that file's provenance and add the applicable attribution/license material to the repository.
